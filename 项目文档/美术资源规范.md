# 美术资源规范

更新：2026-10-21｜适用：新增、生成、导出、转换及接入的项目美术资源

本页是美术格式与转换规则的唯一维护入口；其他任务文档通过链接引用。规范不代表某批资源已经转换或验收，实际结果以该批交接和验证记录为准。

## 格式选择

- **优先生成和使用 WebP。** 新增位图美术、采用图、表情差分、背景、CG、封面与 UI 图片，优先输出 `.webp`，项目运行引用优先指向经过校验的 WebP 文件。
- 生成或编辑工具只能输出 PNG／JPEG 时，先保留原始输出及来源记录，再真正编码转换为 WebP；通过校验后接入。不得只改文件后缀，也不要反复从有损衍生图转码。
- 透明立绘、表情差分、线稿和 UI 优先使用**无损 WebP**，完整保留 alpha；背景和 CG 可在视觉对比通过后使用有损 WebP，并记录质量参数。本次存量迁移以无损转换为默认方案，不借格式转换重新压缩画质。
- 原生 SVG 可继续保留。需要可编辑母版、分层文件或特定工具格式时，保留相应源文件，并另导出适合运行的 WebP；不为统一后缀牺牲矢量或编辑能力。

## 转换与接入

1. 先区分运行素材、采用图、原始输出和证据资料，记录源路径与目标路径。保留尺寸、比例、画面方向、色彩表现及透明度；格式转换不附带裁切、缩放、补背景或修改画面。
2. 使用支持 WebP 的编码器转换，核对实际文件格式、可解码性、像素尺寸和 alpha。无损转换须比较解码后像素；有损转换须另外对照细线、文字、肤色、渐变和透明边缘，确认没有可见损伤。
3. 同步更新受影响的构建源、运行引用、采用清单和当前文档链接，再按项目约定重新生成输出。不得只修改生成的 `story.js`，导致下次构建恢复旧路径。
4. 检查文件存在、引用无断链，并在真实页面检查背景、立绘、差分、CG和封面的加载及透明边缘。格式与像素检查、工程测试、浏览器呈现分别记录；未执行的项标为待验。
5. 清理被替代的运行文件前，确认全部当前引用已切换，原始输出和历史证据仍可追溯。交接记录转换参数、验证结果、保留的例外及未完成项。

## 保留范围

| 资料 | 处理原则 |
| --- | --- |
| QA 截图、历史验收附件和历史发布快照 | 保留原格式及原文件，用于还原当时结果；不因格式规范重写历史证据。 |
| 用户原始实拍、参考图、生成原始输出及来源档案 | 原样保留。需要查看或运行用 WebP 时，新增衍生文件并记录来源关系。 |
| 编辑母版、分层素材、SVG | 保留原生格式；运行所需位图另行导出。 |
| 暂时不能可靠转换的资源 | 保留原格式，在交接写明原因及替代路径；不得把未验证的文件登记为完成。 |

本规范约束后续制作与接入，不要求删除上述原件，也不将图片格式迁移视为剧情、存档或发布验收。

## 项目工具与清单

- 在提供 `sharp` 的 Node.js 环境运行 `node scripts/convert-art-webp.cjs`，对 `assets/` 中的位图美术做无损转换与像素核对；原始参考照片和 `qa-*` 验收拼图自动跳过。原图保留，已被另行修改的 WebP 不会直接覆盖。
- [WebP 转换清单](../assets/webp-manifest.json)记录全部原图／WebP 对应关系、真实尺寸、字节数、指纹和验证结果；[运行清单](../assets/runtime-v0.4-manifest.json)由正式构建生成。
- 更新接入源后运行 `node 任务拆分/三章扩展/build-story.cjs`。转换及验证数据保留于[WebP转换清单](../assets/webp-manifest.json)。
