## 2. 数据转换与角色表现接口

转换输出需要 `sourceMap`：每个正文节点都能回到原文，条件门禁也有来源。以同一选择序列展开新文稿与游戏节点，比较实际读到的正文、分支顺序和结局；只检查字数或“所有节点可达”不足以证明正确。

拟增加人物表现字段，示例如下；**这不是当前已经支持的 API**：

```json
{
  "sourceAnchor": "原文文件、章与短句",
  "nodeId": "冻结契约后填写真实ID",
  "present": ["xiaoman"],
  "character": "xiaoman",
  "form": "human",
  "outfit": "work-apron",
  "pose": "standing",
  "expression": "focused",
  "avatar": { "sameIdentityAndOutfit": true },
  "cg": null
}
```

当前播放器主要用 `expression` 查图片，衣装通过特殊差分键表达，不能自然组合衣服和表情。两种实现需在 S0 试验后择一：

- 推荐：编写“语义组合→已采用完整图片”的解析层。只生产实际出现组合，找不到组合则构建报错；同形态／同衣装的中性回退必须显式登记，不能悄悄换衣服或变回球形。
- 可选：保留现有解析方式，把组合编译为唯一差分键。数据表仍独立记录衣装、表情和姿势，不能让作者手写散落的拼接键。

UI、存档恢复、历史回顾与 CG 退出均读取同一解析结果。画面状态按节点显式计算，不依赖上一个读者曾走过的路径。多人场景先明确当前画面支持的人数和站位；无法容纳时用轮替镜头或 CG，不把未实现的多人舞台写成已支持。

## 3. 60 张 CG 的登记与条件

选片 JSON 是制作输入，正式 CG 注册还需真实资产与实际节点。登记资源路径、标题／替代说明、允许节点、路线、已完成的关键事件、可见条件、退出节点及回顾条件。

必须覆盖：

1. 到达正确节点且条件满足，并成功加载显示图片后才解锁。
2. 预读、错误路径、未执行事件、加载失败、候选预览均不解锁。
3. 离开 CG 恢复相应背景、人物衣装和表情；读档不能残留上次画面。
4. 结局图不串入另一结局；毛狼／飘婚后饭局不进入 PI-E1，FR-E2 不显示文文出席；黄球球不被放入公开群像。新稿没有婚礼现场，不沿用旧婚礼 CG 充当本段剧情。
5. 回顾图库只展示已合法解锁的图，保持原始章节和条件信息，不改变当前路线状态。

## 4. v1.1 存档隔离

建议独立前缀 `bijie-rain:v1.1:`，另记录 `contentRevision`、契约、引擎状态和表现资源版本。最终前缀与修订策略在契约冻结时确定；本轮尚未修改。

- 旧版进度不自动套到新节点。默认 v1.1 新开局，旧存档原字节保留；如未来需要导入，单独设计明确的映射与失败处理。
- 兼容检查在读取剧情状态前完成；不能因缺少新字段退回旧命名空间。
- 新版内部读档重放校验选择、路线、事件和节点；坏档、跨版本档和篡改状态应给出可理解提示，不覆盖原数据。
- 测试用独立端口与新浏览器上下文。除了自动／手动存档，还需隔离已读记录、设置、CG 解锁与回顾状态。测试人员不操作玩家真实存储。
