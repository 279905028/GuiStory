# 版本、来源与复核

- `package-manifest.json`：全部包文件的大小与SHA-256，注明版本、设备待验和本地交付范围。清单自身不列入自身哈希；ZIP外部指纹用于整包身份核对。
- `game/assets/runtime-ten-chapter-manifest.json`：原样保留E09正式运行清单。其 `finalAcceptance:false` 与E10尚有设备待验一致，不代表打包缺失。
- `materials/source/`：17份章节／路线源、十章正文、契约、演出绑定、构建器、采用图来源记录及正式来源映射。运行图在 `game/assets/`；原始照片、PNG母版与历史截图仍保留在原工程，未随运行包重复分发。来源记录中的原始路径是追溯信息，不代表原图随包。
- `materials/e10/`：E10原始汇总与各套JSON结果原样副本。证据记录的路径、环境和时间属于E10，截图和历史测试依赖未随包；不得当作本包离线验收的新结果。
- `materials/provenance.json`：原工程路径与包内路径对应，及正式构建组指纹。

有Node.js时，在包目录执行完整性检查：

```sh
node tools/verify.cjs
```

源重建已在macOS验证，冻结构建器要求POSIX路径。Windows不支持本项逐字复核（工具会明确提示），Linux尚未实机验收。在macOS包目录执行：

```sh
node tools/rebuild-check.cjs
```

第一项核对包的完整性；第二项在自动创建的临时目录拼合源和运行图，只读重新生成四份正式产物并逐字比较，结束清理临时副本。无需联网或第三方库，不改正式游戏和玩家存档。来源快照仅保证当前十章构建；不要执行其中的旧三章构建分支或历史QA入口。

在原工程中重新打包使用 `node 交付/全十章-E11/build-package.cjs`。它先核对当前源与E10版本、只读构建、复制白名单，再固定文件顺序与ZIP时间。相同源／模板生成相同包；若既有交付版内容不同则拒绝覆盖，应更换交付版标识。
