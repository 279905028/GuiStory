# 十章模块与构建接口

更新：2026-10-23｜E09正式接入，E02模块接口保持兼容｜接口冻结于契约 `1.0.0`、正文 `nightshift-20261022-r1`

本页是 E03—E09 的构建交接入口，补充 E01 未指定的模块名称、构建清单和演出绑定格式，不修改故事与状态契约。机器契约中的 `readiness` 保留 E01 交付时快照；最新进度见[当前待办](../../TODO与多窗口提示词-v0.4.md)。

## 1. 使用与边界

从项目根目录执行：

```sh
# 正式十章：E09默认入口
node 任务拆分/三章扩展/build-story.cjs

# E02 小型样例：仅在独立目录生成输出
node 任务拆分/三章扩展/build-story.cjs --ten-chapter --sample

# 只校验，不写输出
node 任务拆分/三章扩展/build-story.cjs --ten-chapter --sample --check

# 自有清单；路径相对项目根目录
node 任务拆分/三章扩展/build-story.cjs --ten-chapter --manifest 任务拆分/全十章/build-manifest.json
```

正式 `build-manifest.json` 已列齐17个真实模块及演出绑定。无参数入口执行E09正式构建，输出根 `story.js`、`assets/runtime-ten-chapter-manifest.json` 与 `校验/E09/` 内的来源映射／构建报告；`--check` 只校验。所有校验通过后才写出，旧产物先保存快照。

演出修改后先执行 `node 任务拆分/全十章/presentation/prepare-bindings.cjs`，正式构建会以 `--check` 校验绑定与准备器一致；源与A06指纹漂移会停止，不静默改用旧故事。`--legacy-three-chapter` 仅用于独立副本中的历史复现，会改写根剧情。

带 `--ten-chapter` 仍只读取独立JSON并隔离输出，不读取旧快照；缺模块、缺绑定或校验失败就退出。

只有显式 `--ten-chapter` 的隔离输出限制在 `任务拆分/全十章/构建/` 的子目录。默认目录名由产物内容指纹决定；相同内容可安全复用，不同内容生成新目录。可使用 `--out-dir 任务拆分/全十章/构建/自选新目录`，已有不同内容或软链接会被拒绝。全部校验成功后才整体写入，不能直接写根目录 `story.js`。

每次隔离输出 `story.js`、`story.json`、`source-map.json` 和 `build-report.json`。报告保留输入指纹、来源版本、图检查及事件见证，明确 `formalIntegration:false`。这些隔离输出没有接入游戏入口；当前正式候选与配套播放器见[E09交接](交接/E09.md)。

## 2. 模块和清单

| 内容 | 文件相对本目录 | moduleId | owner |
| --- | --- | --- | --- |
| 十章共通 | `common/ch01.json`—`common/ch10.json` | `common/ch01`—`common/ch10` | E03 |
| 小满／周栀 | `routes/xiaoman.json`、`routes/zhouzhi.json` | 文件路径去掉 `.json` | E04 |
| 孟遥／叶岚 | `routes/mengyao.json`、`routes/yelan.json` | 同上 | E05 |
| 飘／朋友职业 | `routes/piao.json`、`routes/friends.json` | 同上 | E06 |
| 黄球球 | `routes/huangqiuqiu.json` | `routes/huangqiuqiu` | E07 |

共通模块只拥有本章 `common` ID；单一路线模块拥有本路线第3—10章 ID，即使同一负责人管理两条路线也不能互读专属状态。场景属于本模块同章，禁止借用其他模块的场景。

模块公共字段、节点和状态定义使用 [contract.json](contract.json) 的 `interface`。必需字段全部提供；不认识的模块／节点字段直接报错。JSON 重复键也报错，不能依赖解析器静默覆盖。

- `imports`：精确列出本模块所有指向外部节点的引用，不能多报、漏报或指向未导出节点。
- `exports`：`{"公开节点ID":"同一个本地节点ID"}`。公开入口、共通分流和章出口必须导出；不允许别名或空入口。
- `sourceMap`、`exclusions`、`assetRequests`：必需数组，具体见下节。
- 不允许空节点／空场景模块。正文作者不修改构建器、播放器或生成结果。

构建清单字段：

```json
{
  "schemaVersion": 1,
  "contractVersion": "1.0.0",
  "contentRevision": "nightshift-20261022-r1",
  "mode": "candidate",
  "modules": ["common/ch01.json", "routes/xiaoman.json"],
  "bindings": ["presentation/bindings.json"]
}
```

上面只展示字段，省略的模块不能直接用于 `candidate`。完整路径模板见 [build-manifest.example.json](build-manifest.example.json)。模块与绑定路径相对清单文件，必须留在独立十章源目录，不自动扫描目录或执行 JavaScript 模块。

| mode | 检查范围 |
| --- | --- |
| `sample` | 必须另写 `sample:{start,stops}`；stops 只能是已存在、`next:null` 的 line。允许部分模块与部分原文，但引用仍完全闭合、节点和选项全部可达。 |
| `candidate` | 不允许 sample 字段；必须17个模块，10章入口、56个路线入口、选择、自动事件、后日谈及13个终结齐全，基线所有非空来源行有映射或排除记录。仍只隔离输出。 |

`candidate` 表示完整模块的静态检查模式，不代表 E09／E10 的最终候选验收。当前E09已完成17模块的完整 `candidate`，正式验收范围仍与E10分别记录。

## 3. 来源、日序和状态

来源映射格式为 `{file,startLine,endLine,nodeIds,kind}`，行号从1开始，首尾包含；`file` 为项目根目录相对路径，必须属于契约锁定的10份正文。`kind` 允许 `dialogue`、`narration`、`choice`、`scene-title`、`control`。

- 所有节点都须有来源映射，控制节点也要写依据；每条 `nodeIds` 指向本模块同章真实节点。
- 正文来源不能越出自己的 `chapters[].sections`。共通可排除文件首尾导航，但不能认领路线段落。
- 同一非空正文行只可有一条 `dialogue/narration` 映射；若一行拆成多个节点，在这一条的 `nodeIds` 中列齐。控制条件和场景标题可共享依据，完全重复的映射记录会被拒绝。
- `exclusions` 为 `{file,startLine,endLine,reason}`；reason 只允许 `navigation`、`reading-rule`、`heading-only`、`choice-label-excerpt`。正文与排除冲突会被拒绝，按钮摘录例外须用 `choice-label-excerpt` 显式标记，并保留完整回答的正文映射。
- 完整候选按非空来源行计算映射／排除覆盖。该检查不证明对白逐字正确，也不证明排除理由合理；逐句原稿核对由 E10 完成。
- 两处自动事件必须独占契约指定的原文行，正文映射覆盖其来源锚点，`text` 与该行一致；`onEnter.requires/setFlags` 原样匹配契约。

场景提供 `chapter/title/bg/time/chronology/location/day/dayLabel`。构建器检查并输出显示字段：普通日序用 `第N天`；两年后 `day:null,dayLabel:"两年后"`；中性章末 `day:null,dayLabel:该章days,time:"章末",location:""`。`chronology.clock` 若存在须等于场景 `time`。第六章孟遥／叶岚的第30天回叙保留 `mode:"flashback"`。

选择的 ID、顺序、标签、状态值和可见条件必须与契约相同；`text` 是字符串，原稿无独立提问可为空。状态只能在契约的唯一写入点赋值，不允许通过演出绑定增加写入。

图校验按“节点＋完整 flags”合并状态，从初始状态枚举；门禁按首命中、选项按 AND 解析，自动事件先检查前置条件再赋值。检查全部静态环、节点／选项可达、路线隔离、隐藏资格、形态和结局条件，并保留关键选择见证。门禁各分支命中数也会记录；每个门禁分支是否都有见证、每条结局路径是否恰好经过一个适用后日谈，由 E10继续验证。这不是实际播放器测试。

## 4. 演出与资产请求

绑定文件可拆分多份；重名资源或同一目标同一字段的重复覆盖会报错。

```json
{
  "schemaVersion": 1,
  "contractVersion": "1.0.0",
  "contentRevision": "nightshift-20261022-r1",
  "characters": {},
  "backgrounds": {},
  "cgs": {},
  "scenes": {},
  "nodes": {}
}
```

- `characters`、`backgrounds`、`cgs` 是独立资源字典；角色 ID 必须在契约中，背景值为路径／语义字符串，CG 项必须有 `image`。
- `scenes` 按现有场景 ID 覆盖 `bg`；`nodes` 按现有节点 ID 覆盖该类型支持的 `character/expression/avatarExpression/bg/cg`。不能覆盖正文、状态、跳转、日序或地点。
- 节点和场景引用的角色／背景／CG 键必须存在。资源是否真实、已采用、WebP 合规，差分是否匹配具体形态，以及画面效果由 A06／E09／E10继续验证。
- `assetRequests` 可写 E01 语义 ID 字符串，或 `{id:"e01-art-chNN",a01Ids:["A01资源ID"]}`。E02检查 E01语义和所属章节／路线；A01映射及最终采用另行核验。

样例只用 `sample://background`，没有注册真实美术，也没有生成图片。正式资源遵守[美术资源规范](../../项目文档/美术资源规范.md)。
