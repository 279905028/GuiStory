更新：2026-10-22｜E01 已完成｜契约 `1.0.0`｜正文 `nightshift-20261022-r1`

## 1. 本轮采用范围

用户已确认：**采用当前网吧夜班版十章稿作为本轮工程基线，后续修改再升级版本**。包含黄球球第55天自主变为人形的修订。十章正文原样保留；确认正文不代表确认人形基础图的外观，也不代表游戏已经更新。

- 人工阅读入口：[十章正文](../../项目文档/故事/全十章审阅稿/README.md)。
- 精确数据：[contract.json](contract.json)。其中包含10份正文的 SHA-256、来源行、日序、56个路线章段边界、19处选择／43个选项、21个状态字段、13个结局、资产语义需求与后续依赖。
- 可复核检查：`node 任务拆分/全十章/verify-contract.cjs`；[检查结果](校验/E01/verification.json)、[交接](交接/E01.md)。

本契约对本轮基线的确认，取代旧阅读辅助文档中“待用户修改”的制作前置状态。正文仍可修改，但先升级 `contentRevision`、重取指纹、评估受影响模块，再继续制作；不能静默替换既定来源。接口有破坏性修改时升级契约主版本，由 E01 协调所有读写方。

## 2. 所有权与模块边界

| 任务 | 独占内容 | 接口职责 |
| --- | --- | --- |
| E01 | 本契约、机器契约及 E01 检查／交接 | 统一节点、状态、正文版本；不制作正式故事节点 |
| E02 | 十章模块读取与构建框架 | 实现下述数据格式；先隔离输出，不能用空模块覆盖游戏 |
| E03 | `common/ch01.json`—`ch10.json` | 章前共通、选线与路由、章末、第十章公共后日谈；前两章隐藏门 |
| E04 | `routes/xiaoman.json`、`zhouzhi.json` | 各自第3—10章及结局 |
| E05 | `routes/mengyao.json`、`yelan.json` | 各自第3—10章及结局、重逢／初见回收 |
| E06 | `routes/piao.json`、`friends.json` | 飘持续关系、朋友职业线；审核 E03 的飘后日谈条件与文本 |
| E07 | `routes/huangqiuqiu.json` | 隐藏路线、第42天铺垫、第55天变身与后续人形 |
| E08 | 播放器、引擎、存档及运行模块 | 执行状态／形态协议；不重新决定剧情 |
| E09 | 统一正式构建、演出绑定、`story.js`、运行清单 | 接收 E02 所有权和各任务成果后构建 |

上述模块路径均相对本目录，**是后续交付接口，文件尚未制作**。正式构建入口仍为 `node 任务拆分/三章扩展/build-story.cjs`；E01 没有修改构建源，因此本轮不运行该命令。

模块为 JSON，公共字段：`schemaVersion:1`、`contractVersion`、`contentRevision`、`moduleId`、`owner`、`scenes`、`nodes`、`imports`、`exports`、`sourceMap`、`exclusions`、`assetRequests`。精确定义见机器契约 `interface.moduleFormat`。

`scenes`、`nodes` 均按 ID 索引；节点字典键必须等于 `node.id`。`imports` 列外部节点，`exports` 将公开 ID 映射到本模块同名真实节点。E02 检查版本一致、ID 唯一、引用完整和读写权限。新版正文从独立十章源建立，不继承旧三章快照。

运行产物保留 `version:1` 与 `backgrounds`。选项最小形状为 `{label,value,next,requires?}`，门禁分支为 `{flag,value,next}`；`choice.text` 必须是字符串，原稿无独立提问时可为空，不另编台词。结局保留 `character/expression` 等演出字段。E01 的选项目录没有实际 `next`，不能直接当作可运行节点。

## 3. 日序与章入口／出口

| 章 | 时间 | 交接重点 |
| --- | --- | --- |
| 1 | 第1—7天 | 记录三拍、孟遥重逢；全章 E03 |
| 2 | 第8—14天 | 回应节奏、约局解释、叶岚初见；隐藏相识；全章 E03 |
| 3 | 第15—21天 | 共通后七线选一；飘第21天确定关系 |
| 4 | 第22—24天 | 每线独立二选一经历 |
| 5 | 第25—29天 | 共通回收第二章约局解释 |
| 6 | 第30—34天 | 同一顿饭；共通至第31天，孟遥／叶岚再补叙第30天饭后 |
| 7 | 第35—45天 | 逐线回收第四章；球球第42天仍球形 |
| 8 | 第46—60天 | 第52天试排；球球第55天17:00段内变身 |
| 9 | 第61—90天 | 确认轮班；五线选择关系，飘只读取第三章状态 |
| 10 | 两年后 | 共通序言→唯一适用飘后日谈→所选路线结局 |

节点前缀为 `tc_cNN_<scope>_`，场景前缀为 `ts_cNN_<scope>_`。`scope` 只允许 `common` 或七个路线 ID；`NN` 为 `01`—`10`。段内 ID 稳定命名，不以全文行号充当节点 ID。

- 每章公开入口：`tc_cNN_common_entry`。第一、二章全程共通。
- 第三章选择：`tc_c03_common_route_choice`，只写一次 `route`。第4—10章使用对应 `common_route_gate` 读取已选路线。
- 路线公开入口：`tc_cNN_<route>_entry`，第3—10章共56个；任何路线不得跳入另一条路线。
- 第1—9章统一出口：`tc_cNN_common_exit`，类型 `end`，其 `next` 指向下一章共通入口；`nextChapter` 使用实际下一章标题。路线末尾都回到本章出口。
- 第十章无公共章末。路线正文进入本路线对应终结 `end`，无 `next`；13个终结 ID 与条件见 `endings`。公共后日谈不得当成结局或在飘模块重复播放。

日序以 `scene.chronology` 记录，分 `story-day`／`two-years-later`，并显式标识 `present`／`flashback`。第六章两处回叙不能被当成日期错误或重复饭局；两年后不推算具体日历日期，也不强制同一天。第九章朋友分支正文内的小满第82天、周栀第88天、孟遥第81天、叶岚第86天须拆出相应时间，不沿用前一场标题。

E02 同步输出播放器使用的 `day/dayLabel/time/location`。第六章第37行已是第31天凌晨，第39行是第31天06:00。共用章末使用独立中性场景，`chronology.domain=chapter-range`、`day=null`、`dayLabel=章节范围`、`time=章末`、`location=""`；不冒充刚结束路线的具体时间地点。

## 5. 隐藏线、自动事件与形态

第14天隐藏门要求 `qiuSignal=record AND qiuReply=reply`。第8天“敲回节奏”始终可选，但未记录三拍时只能进入未获回应的正文。四种组合中仅“记录＋回应”进入正式相识。

第三章黄球球选项额外要求 `qiuMet=true`，缺失资格时直接隐藏。身份段位于隐藏门之后；前两章的门外声音不提前展示球球姓名、立绘或头像。相识段最后一行 `tc_c02_common_qiu_met` 用 `onEnter.setFlags` 记录已读过相识。

形态切换锚点是 `tc_c08_huangqiuqiu_human_reveal`：第八章第527行“坐在我面前的，已经是个……”进入时写入 `qiuForm=human`。第485行场景入口到搭手等前段保持球形；第525行变化过程可用过渡演出，不能一进入17:00场景就换成人形。第九章和第十章两种关系都延续人形。

保留 `line / choice / gate / end` 四种节点及现有引擎公开方法。只增加确定性 `line.onEnter.setFlags` 和 `story.initialFlags` 能力；当前引擎尚未实现。自动赋值仅允许机器契约登记的两处事件，不能伪造成玩家选择。执行顺序为候选状态→解析门禁→校验整批赋值→应用→记录历史→一次提交；本次跳转失败不得留下部分修改。

事件前置条件同时写入 `line.onEnter.requires`：E02／E10 验证前置门禁与正式图保证条件，E08 进入该行时再次按 AND 检查。不满足就报错，不执行赋值；不能将它写成引擎不处理的行顶层 `requires`。

条件沿用“自有字段＋严格相等”。选项 `requires` 为 AND；多条件 `gate` 通过串联实现。穷尽枚举路由使用 `exhaustive:true, default:null`，合法状态必须命中，非法状态报错并保留原状态，不能默认为某条路线。

角色资源结构约定 `characters.huangqiuqiu.forms.sphere / human`；各自提供 `image`、`expressions`、`avatarImage`、`avatarExpressions`、`presentation`。播放器根据当前状态同时解析立绘和说话头像；不得全局替换旧球形图片，缺图不得悄悄回退到另一形态。现有回顾仅显示姓名文字；若显示历史形象或回到旧行，必须按历史前缀重放得到该行的形态，不能用当前人形回填过去。

形态状态名 `sphere` 对应现有显示值 `presentation:"orb"`；人形对应 `"human"`，保持现有等比球形排版语义。

## 6. 结局、后日谈与存档

小满、周栀、孟遥、叶岚、黄球球各有恋人／朋友两种结局；飘沿用第三章关系形成两种；朋友职业线独立完结，共13种。

第十章公共后日谈只有两个互斥段：`route=piao AND piaoRelationship=dating` 进入文文与飘仍交往的饭局；其他全部合法路径进入飘与毛狼婚宴。随后再进入所选路线的独立结局。黄球球不参加婚宴、不向普通人物显露；飘第九章不得重选关系。

新存档前缀固定为 `bijie-rain-demo:ten-chapter:nightshift-20261022-r1:`。契约版本、正文修订、存档内容版本分别记录。十章内容不读取、迁移、覆盖或删除旧空间，不调用旧“两句改写”补丁。首次十章内容版本设为1，现有引擎状态结构版本仍为1；若 E08 必须改变结构，先升级契约再实现。

恢复从初始状态和完整选择轨迹重放，校验 flags、history、choices 与检查点。重选回到所选选择之前的前缀；其后的关系、日常选择、形态和历史全部重建。第三章重选保留前两章真实相识，但不保留后续人形；第九章关系重选保留已经发生的变身。测试只能使用隔离存储。

新数据必须声明 `requiredCapabilities`。E08 启动时核对支持能力，避免旧引擎忽略新增字段后仍继续运行。E02 只能先生成隔离样例；E09 须在配套播放器具备这些能力后接入正式产物。

## 7. 资产需求与未完成范围

A01 负责逐章逐线去重、复用判断、尺寸、资源 ID 与分镜；A06 才登记正式采用，E09 绑定真实资源。文文维修道具、孟遥相机、叶岚旧领班夹板、师匠旧维修身份须复核。资源遵守 [WebP 规范](../../项目文档/美术资源规范.md)。

本轮没有尚待决定的故事情节；用户已采用当前稿。以下依赖继续保留：

本轮检查只证明契约内部与来源一致。抽象状态组合验证不等同于正式故事路径、引擎恢复或浏览器验收；旧三章仍是当前游戏。
